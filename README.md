# AliBulkFinder v0.3.3 — длительный поиск с паузами и ручной остановкой

В версии 0.3.3 превышение локального лимита и ответ `HTTP 429 / RGV587` **не завершают поиск**. Программа ждёт и затем автоматически продолжает ту же операцию, пока задачи поиска не будут выполнены либо пользователь не нажмёт **«Остановить поиск»**. Это не средство обхода антибот-защиты и не обещание, что сайт обязательно разрешит дальнейшие запросы.

## Новое поведение

1. **Поисковая серия:** по умолчанию не более **18 новых MCP-вызовов**, затем **10 минут паузы**, снова 18 вызовов и т. д. Кэшированные ответы не расходуют серию. В отличие от v0.3.2, лимит **не останавливает** весь поиск.
2. **При HTTP 429:** сообщение появляется в нижнем журнале программы, далее выдерживается **10-минутная** защитная пауза и **повторяется тот же запрос**. Если приходит новый 429, программа снова ждёт; повторяется до успешного ответа или остановки пользователем. Защитная пауза после 429 записывается в `cache/blocked_until.json` и сохраняется при перезапуске программы. Если сайт долго ограничивает запросы, лучше прекратить поиск вручную и дать сервису больше времени.
3. **Другие ошибки:** неудавшуюся страницу поиска программа повторяет после настраиваемой паузы (по умолчанию 2 минуты); если не удалось открыть отдельную карточку/SKU, она записывает ошибку в журнал и переходит к следующему товару. Ошибки конфигурации или запуска программы по-прежнему могут завершить операцию — исправить их ожиданием нельзя.
4. **Остановка:** новая кнопка **«■ Остановить поиск»** доступна во время поиска, ожидания или перепроверки SKU. Ожидание прерывается обычно за долю секунды; текущий незавершённый запрос отменяется. Уже обработанные предложения **сразу добавляются в таблицу**, не теряются при остановке и могут быть экспортированы в CSV/JSON. Поиск сам заканчивается по выполнении всех заданных страниц/карточек.
5. **Ожидаемое время:** строка состояния отображает приблизительное оставшееся время, число завершённых запросов/попаданий в кэш, количество новых запросов и **обратный отсчёт паузы**. Оценка учитывает плановые перерывы, но может сильно изменяться при новых блокировках, пропуске страниц, отсутствии товаров или скорости сайта.

## Отдельный блок «Защита от ограничений AliExpress»

| Поле | Значение по умолчанию | Назначение |
|---|---|---|
| Вызовов до паузы | `18` | Количество *новых вызовов MCP* в серии; внутри одного вызова может быть несколько HTTP-запросов |
| Интервал, сек. | `4` | Минимальный интервал между запуском двух вызовов; внутренний MCP может дополнительно задерживать HTTP-запросы |
| Пауза по лимиту, мин. | `10` | Плановый отдых после серии |
| После HTTP 429, мин. | `10` | Ожидание перед повтором заблокированного запроса |
| После сбоя сети, мин. | `2` | Ожидание перед повтором страницы поиска после других сбоев |

**Пример:** нужно выполнить приблизительно 40 некэшированных вызовов. При лимите 18 программа выполнит 18, подождёт 10 минут, выполнит ещё 18, подождёт 10 минут и завершит оставшиеся четыре. При ответе 429 добавится ещё отдельная защитная пауза. Оценка времени — ориентир, не гарантия.

## Обновление со старой версии

1. Закрой AliBulkFinder (если идёт поиск — сначала нажми «Остановить поиск» и при необходимости экспортируй результаты).
2. Распакуй архив **поверх прежних исходных файлов**, сохрани `settings.json`, `.venv` и папку `cache/`.
3. Запусти привычный `start.bat`. Переустановка зависимостей не требуется, если они уже работали в v0.3.2.
4. Старые настройки загрузятся; новые пять полей защиты получат значения по умолчанию и будут сохраняться в `settings.json`.

**Совместимость со старой защитной паузой:** если версия 0.3.2 ранее записала ожидание на 30 минут в `cache/blocked_until.json`, новая программа не сокращает уже записанный срок. Для следующих ответов 429 применяется выбранная настройка (по умолчанию 10 минут).

**Ограничения:** программа должна оставаться запущенной; при закрытии и новом запуске весь процесс поиска автоматически не возобновляется с точной прежней позиции, хотя кэш помогает повторному поиску. Компьютер не должен переходить в сон. Тесты выполнены на локальных имитациях MCP, а не на настоящих ответах AliExpress.ru с твоего подключения.

## История: v0.3.2 и более ранние версии (описание прежнего поведения)

### v0.3.2 — прежняя политика: остановка при HTTP 429

**Причина ошибки по журналам пользователя:** 29.10.2026 сайт aliexpress.ru ответил на `/aer-webapi/v1/search` сообщением `RGV587 / HTTP 429` («слишком частые запросы с этого IP»). Предыдущая версия показывала вторичный `JSONDecodeError`, пытаясь разобрать текст блокировки как JSON. Код в v0.3.2 перехватывает эту ситуацию и сообщает причину прямо в интерфейсе. Это **не обход защиты AliExpress**.

## Что поменялось

- **Меньше запросов по умолчанию.** `Изучить карточек` теперь 8 вместо 25 (старые настройки остаются, если они сохранены в `settings.json`). Новые поля: **«Лимит API-вызовов»** — по умолчанию `18` за один поиск, и **«SKU на карточку»** — по умолчанию `2` вместо всех четырёх. Оба параметра можно изменить прямо в интерфейсе. Лимит считает внешние обращения программы к MCP; сам MCP может выполнять несколько HTTP-запросов для одного такого обращения.
- **Интервал:** минимальная задержка внутри MCP установлена в **4 секунды** между HTTP-запросами к AliExpress (если переменная среды `AE_MIN_INTERVAL` задаёт больше — используем большее значение). Интервал не гарантирует отсутствие блокировки.
- **Дисковый кэш `cache/`:** успешные поисковые ответы сохраняются на 6 часов, а данные карточек/цен/доставки — на 45 минут. Повторный поиск с теми же параметрами в эти сроки может использовать кэш вместо сети. Вся сумма из кэша — прежняя **оценка по городу**, а не подтверждённая текущая цена; проверяй корзину перед покупкой. Название города входит в ключ кэша. Никаких паролей или токенов в кэше нет.
- **При HTTP 429:** немедленно прекращаются новые автоматические обращения; без циклических повторов. Защитная пауза программы на **30 минут** сохраняется в `cache/blocked_until.json` даже после перезапуска. Это *минимальная локальная пауза*, а не обещание, что AliExpress разблокирует доступ за 30 минут. Если сервер продолжает ограничивать доступ, лучше прекратить попытки и дать ему больше времени.
- **При исчерпании лимита запросов:** поиск завершается с пояснением. Уже рассчитанные строки остаются в таблице, успешные ответы сохраняются в кэше. Если новый поиск остановился до получения хотя бы одного предложения, прежние результаты таблицы не удаляются.
- **«Очистить кэш»** удаляет сохранённые цены и выдачу, но **не снимает защитную паузу** после HTTP 429.
- **«Перепроверить SKU»** всегда делает свежий запрос (не использует кэш) при отсутствии блокировки и с учётом защитного интервала. Не нажимай эту кнопку многократно подряд.

## Что делать прямо сейчас

1. **Не повторяй поиск несколько раз подряд**, если сайт уже вернул 429. Дай ограничению на стороне AliExpress истечь; продолжительность неизвестна и может превышать нашу локальную защитную паузу.
2. Распакуй новую версию поверх старой папки, **сохрани `settings.json` и `.venv`**. Повторно устанавливать библиотеки не требуется.
3. Для первого контрольного запуска выбери **один поисковый запрос**, **1 страницу**, **3–5 карточек**, **1–2 SKU на карточку** и лимит **10–15 API-вызовов**. Далее увеличивай охват осторожно.
4. Если появляется CAPTCHA, можно запустить `start_visible_browser.bat` и пройти проверку вручную. Это не гарантирует доступа к API и не заменяет требования сайта по частоте обращений.
5. Если автоматические запросы продолжат блокироваться, разумный запасной путь — **ручное открытие найденных карточек в обычном браузере** с последующей проверкой итоговых сумм через корзину. Автоматические запросы не стоит пытаться бесконечно повторять через новые IP.

**Проверка:** 22 автономных теста прошли, включая тесты интерфейса в виртуальном дисплее. Живые запросы к AliExpress из среды сборки не выполнялись; фактическое снижение блокировок на твоём подключении пока не подтверждено.

# AliBulkFinder v0.3.1 — диагностика ответа AliExpress / MCP

В этой версии добавлен диагностический журнал `alibulkfinder_debug.log` в папке программы. При ошибке программа записывает полный Python traceback, точку сбоя и тип/короткий фрагмент некорректного MCP-ответа (если проблема в преобразовании JSON). Журнал НЕ содержит автоматически собранных HTTP cookies, токенов авторизации или полного HTML-ответа. В диагностике могут присутствовать поисковые запросы, город и идентификаторы товаров; просмотрите файл перед отправкой.

**Чтобы уточнить причину:** запустите `start_diagnostic.bat` и повторите поиск. Скрипт запишет stderr дочернего MCP-сервера в `alibulkfinder_console.log`, а ошибки приложения — в `alibulkfinder_debug.log`. После ошибки откройте `alibulkfinder_debug.log` (его путь также появится в окне ошибки). Отправьте последние записи обоих журналов (после просмотра на предмет личных данных). Если увидите ошибку запуска Chromium, проверьте установку Playwright и попробуйте `start_visible_browser.bat`. Изменять `setup_windows.bat` и переустанавливать `.venv` не нужно при обновлении с v0.3.

# AliBulkFinder v0.2 — поиск оптовых предложений AliExpress.ru

Небольшая программа для Windows с графическим интерфейсом. Ищет предложения на `aliexpress.ru`, учитывает **количество физических штук в лоте**, оценивает итоговую стоимость для заданного количества товара с доставкой **в заданный город** и позволяет вручную подтвердить фактическую сумму, показанную в корзине. Исходный код открыт: все файлы проекта — обычный Python.

**Статус: рабочий прототип.** Офлайн-алгоритм расчёта тестируется автоматически. Сквозная проверка на живом AliExpress.ru из среды разработки не проводилась: сайт и GitHub недоступны из этого окружения. Сервис сторонний и неофициальный — методы могут измениться.

## Первый запуск в Windows

1. Установи **Python 3.10 или новее** (при установке включи опцию `Add python.exe to PATH`). Понадобится доступ в интернет, в том числе к GitHub. На Windows должна быть стандартная библиотека Tkinter (обычно входит в официальный установщик Python).
2. Распакуй архив проекта и дважды запусти `setup_windows.bat`. Этот шаг создаст `.venv`, установит зависимость `aliexpress-ru-mcp` и Chromium для Playwright (скачивается автоматически).
3. Запусти `start.bat`.
4. Измени город, адрес/ПВЗ, ключевые слова, нужное количество и фильтры. Нажми «Найти и рассчитать».

Если сайт показывает CAPTCHA, можно изменить настройку `AE_HEADLESS=0` в среде запуска MCP, чтобы видеть браузер и самостоятельно решить проверку. Не пытайся обходить защиту сайта или выполнять слишком частые запросы.


## Новое в v0.3 — компактный интерфейс и стандартные сочетания клавиш

- Во **всех редактируемых полях** (поисковые запросы, город, адрес, количество, фильтры, диапазон цены и др.) работают `Ctrl+C` — копировать выделенное, `Ctrl+V` — вставить, `Ctrl+A` — выделить всё, `Ctrl+X` — вырезать. Поддержаны русская и английская раскладки Windows. **Кнопки «Вставить», «Копировать», «Выделить всё» удалены**. Копирование без выделения ничего не меняет, как в обычных текстовых редакторах.
- Поле **«Поисковые запросы» расположено в левой половине настроек**. Справа — компактные поля города, адреса и объёмов поиска. Ширина коротких полей уменьшена, их содержимое и поведение не изменились.
- Область **предложений** получает больше свободной высоты: настройки и фильтры сгруппированы плотнее, журнал событий сделан компактнее. Таблица растягивается вместе с окном.
- При запуске **Windows-окно автоматически разворачивается** (`zoomed`): видны панель задач и кнопки управления окном. Можно восстановить или изменить размер обычным способом. На Linux разворачивание зависит от оконного менеджера.
- Все настройки и структура экспортируемых данных совместимы с v0.2. При обновлении распакуй новые исходники поверх старых, **сохрани `settings.json` и `.venv`**, повторная установка не нужна.

## Реализовано в v0.2 — фильтр названий и полной цены

**Поисковые запросы.** Многострочный редактор (один запрос на строку); редактирование и работа с буфером обмена — стандартными клавишами Ctrl+C / Ctrl+V / Ctrl+A / Ctrl+X. Действует для всех редактируемых полей интерфейса.

**Фильтр названий.** В поля «Обязательные слова/фразы» и «Нежелательные слова/фразы» введи термины через **запятую, точку с запятой или перевод строки**. Обязательные условия объединяются по **ИЛИ**. Поиск нечувствителен к регистру и использует вхождение подстроки: `рулетк` подходит и для «рулетка», и для «рулетки»; `badge reel` — как последовательность слов. Это текстовый фильтр, а не морфологический анализ; фотография или комплектация могут не соответствовать названию.

- **Строгий:** карточка допускается, только если в её названии есть хотя бы одно обязательное слово/фраза. Если в ней одновременно есть искомое и исключаемое слово (например, `badge reel with lanyard`), товар **оставляем с пометкой «сомнительно»** — там может быть подходящий вариант. Если есть только нежелательные слова — исключаем.
- **Мягкий:** кроме подходящих показывает и сомнительные названия без обязательных слов, но исключает товары с нежелательными словами и без искомых.
- **Без фильтра:** не проверяет слова.

Сначала проверяется заголовок в результатах поиска, чтобы не открывать явно неподходящие карточки. Затем повторно проверяется полное название с карточки. При изменении условий фильтрации **названий** нужно запустить поиск заново. Изменение диапазона **цен** применяется к уже найденным результатам сразу.

**Фильтр итоговой цены:** «Минимум за весь заказ, ₽» и «Максимум за весь заказ, ₽». Можно заполнить любое одно поле или оба. Границы включены, допускается дробная часть через запятую или точку. Это стоимость **всех приобретаемых лотов для заданного количества физических штук, включая доставку, с учётом известной скидки**. Это не цена за единицу и не отображаемая в поиске минимальная цена одной карточки. Примеры: `1500`–`2500` для заказа на 200 шт., без пересчёта этих границ на одну штуку.

При включённом диапазоне товары с **неизвестной полной стоимостью** по умолчанию **скрыты**, поскольку их нельзя достоверно отнести к диапазону. Чтобы вручную проверить такой вариант, включи «Показывать без известной итоговой цены»: неизвестные предложения станут доступны для открытия и ручного подтверждения; предложения с **известной** стоимостью вне диапазона остаются скрыты. Итог, подтверждённый в корзине, имеет приоритет над оценкой по городу. Экспорт CSV/JSON содержит **только видимые** строки с применённым текущим ценовым фильтром.

**Почему верхняя граница не сокращает число всех запросов доставки заранее?** До расчёта количества, скидок и доставки неизвестно, выйдет ли карточка за лимит. Поэтому сначала собираются точные/доступные оценки, и уже потом они отбираются по полной цене. Игнорировать предложение только из-за высокой цены одного лота было бы ошибкой при оптовых скидках.

Если итоговой цены нет из-за ограничения API в 99 лотов или неопределённой доставки, товар считается непроверенным, а не бесплатным.

## Что программа учитывает

- `200 шт.` — требуемый объём **физических штук**, а не 200 лотов.
- Разные SKU/комплектации одного товара и упаковки по 1, 10, 20, 50, 100 шт., если размер упаковки прямо указан на странице или в варианте товара.
- Товар × необходимое число лотов; ограничения по остатку; допустимый избыток товара.
- Доставку, запрошенную API именно на количество лотов (если 1–99), и доступные купоны по порогу заказа. Цена и доставка — анонимные данные.
- Неизвестная доставка показывается как `—`, **не как ноль**. Для отдельных товаров на 200 штук API не позволяет проверить полную цену одним запросом.
- Можно уточнить комплектность SKU вручную, перепроверить доставку, открыть карточку и вручную ввести стоимость, подтверждённую в корзине.
- Отчёт CSV с разделителем `;` и кодировкой UTF-8 BOM (Excel открывает корректно) либо полный JSON.

## Значение статусов

- **ОЦЕНКА ПО ГОРОДУ** — API магазина вернул стоимость товара и доставки для количества лотов и выбранного города. Это **не цена корзины для личного аккаунта/адреса**.
- **ДОСТАВКА НЕИЗВЕСТНА** — цена товара известна, но доставка не подтверждена: полная сумма отсутствует.
- **НУЖНА ПРОВЕРКА** — не определено число штук в лоте, API не поддерживает нужное число лотов (>99), или возникла ошибка получения котировки.
- **ПРОВЕРЕНО В КОРЗИНЕ** — конечную стоимость вручную ввёл пользователь после проверки количества и адреса в браузере.

Сортировка в таблице сначала по степени проверки, затем по стоимости: **расчёт по городу не приравнивается к сумме корзины**. Экспорт содержит обе величины.

## Что программа пока НЕ делает

- Не получает личную цену и фактический итог оформления заказа автоматически (нет входа в аккаунт и работы с корзиной).
- Не оформляет и не оплачивает заказы.
- Не оптимизирует смешанные заказы из разных продавцов (там другие условия объединения доставки и купонов).
- Не подтверждает точную стоимость на улице/ПВЗ: внешний MCP-сервис поддерживает **город**, но не полный адрес. Адрес программы используется лишь как подсказка при ручной сверке и сохраняется в **локальном** `settings.json`.
- Не гарантирует, что найден каждый товар на площадке. Поиск ограничен параметрами программы, лимитом запросов и ответами самого сайта.
- Не заменяет проверку соответствия предмета — название «рулетка» может означать совсем другой товар.

## Проверка алгоритма без интернета

В папке проекта выполни `python -m unittest discover -s tests -v` (10 тестов расчёта и фильтров, а также 3 GUI-теста; GUI-тесты без графического дисплея пропускаются). Для тестов интернет и внешние библиотеки не нужны.

## Приватность и технические детали

Адрес и поисковые запросы хранятся в папке программы в `settings.json`. К стороннему MCP-сервису передаётся **только город**, товар и количество. Логин, пароли и платёжные данные не запрашиваются. Для установки используются открытые исходники стороннего проекта [SZhukovWork/aliexpress-ru-mcp](https://github.com/SZhukovWork/aliexpress-ru-mcp), лицензия MIT. Просьба соблюдать ограничения и условия использования AliExpress.

При желании можно работать через VPN/прокси, установив переменную окружения `AE_PROXY`, поддерживаемую источником данных. Это не гарантирует доступность сайта.

Если для запуска требуется пройти CAPTCHA в видимом браузере, можно попробовать `start_visible_browser.bat`: он задаёт для дочернего сервера `AE_HEADLESS=0`. Эта настройка открывает окно Chromium **только когда сервер создаёт новую сессию**; она не гарантирует обход проверок и не открывает личный аккаунт.
